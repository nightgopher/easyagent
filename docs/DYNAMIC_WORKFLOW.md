# 动态工作流

在编程会话中发送 `/workflow <任务>`，Agent 可生成 TypeScript 流程，组织多个角色并行或顺序工作。在管家会话使用同一命令时，会创建编程会话并将任务交给它，使用主机默认工作区；其他业务 Agent 会话请改用编程会话。桌面端「设置 → 动态工作流」展示运行、节点及角色会话，可取消或在确认后恢复中断的运行。

桌面对话中的工作流卡片展示引擎分析出的阶段、角色与依赖关系；角色会话可直接打开。运行期间约每 3 秒更新，断线时标注最后状态。关系是脚本的静态分析结果，标为「可能」的关系不代表一定执行。旧运行或图数据超过 1 MiB 时退回展示已有角色与状态，不推测依赖关系。

运行主机需要 PATH 中可用的 Node.js 22.13 或更高版本；客户端连接远程主机时检查的是远程环境。Node 本身不随 EasyAgent 分发。EasyAgent 内嵌固定版本的 ZCode 引擎代码，首次使用的数据目录中会提取引擎文件；源码和许可见 `workflow-runtime/vendor/`。构建引擎请运行 `scripts/build-workflow-runtime.sh` 并提交生成的压缩文件。

每次运行最多四个并行角色，最多四个运行，超时 30 分钟。角色复用父会话的工作区、模型、工具约束及审批回调。引擎不提供直接文件或网络 API，操作通过角色工具执行。进程隔离不等同操作系统安全沙箱。

工作流事件存储在数据目录 `dynamic-workflows/<run-id>/journal.sqlite`，每次写入完成后才确认。已完成的步骤可在恢复时复用；**中断时正在执行的步骤可能已经产生外部副作用**，恢复可能再次执行，因此必须先检查记录并在桌面界面确认。旧版 JSONL 日志暂不支持恢复，不会静默当作新运行处理。
