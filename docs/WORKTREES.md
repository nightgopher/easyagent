# Worktree 开发指南

面向多任务、多会话并行开发的工作约定：何时隔离、谁提交、如何收尾。分支命名与提交格式见[贡献指南](CONTRIBUTING.md)，架构背景见[架构](ARCHITECTURE.md)。

## 何时需要隔离

- 两条任务线要同时进行且互不等待。
- 长任务（大重构、发版验证）期间主目录还要可用。
- 实验性改动需要与主线隔离验证。

单个任务顺序开发不需要 worktree：在主目录开短期 `feat/`、`fix/` 或 `docs/` 分支即可。不为同一任务重复创建副本；优先复用合适的既有工作副本。

## 创建与查看

```bash
git worktree add ../easyagent-<task> -b <task-branch>   # 从当前 HEAD 创建
git worktree list                                        # 查看全部副本
git worktree remove ../easyagent-<task>                  # 移除（需无未处理改动）
git fetch --prune origin                                 # 清理失效远端引用
```

不直接删除 worktree 目录，不用强制删除、`reset --hard` 或覆盖文件来制造干净状态。

## 并行会话纪律

多个会话在同一仓库工作时（无论主目录还是 worktree），混乱通常来自提交边界不清：

- **谁产生，谁提交**。每个会话只提交自己任务范围内的改动；提交信息描述自己真正做过的事。接手他人改动前先读 diff、确认对方任务已结束且获得授权。
- 提交前 `git status` 核对暂存区，不夹带他人未提交或未跟踪的文件。不用 `git add -A`，显式列出路径。
- 需要绕开他人暂存内容提交时，用 `git commit -- <路径>` 做路径限定提交。
- 不修改、不回退其他会话正在使用的文件。发现自己没做过的改动（工作区、暂存区、分支）先停下核实，不当作垃圾清理。
- **开工前查重**。认领一个任务（尤其来自 issue）前，先看 open PR 列表、本地/远端分支和相关文件的未提交改动；已有会话在做同一任务时不并行开工，协调分工（一方实现、一方评审或补测试）或换任务。两个会话同时迭代同一批文件会互相覆盖，谁的结果都无法成立。
- **提交前后核对分支**。共享主目录时其他会话可能切换 HEAD：提交前 `git branch --show-current` 确认在预期分支，提交后 `git log --oneline -1` 核对落点。发现提交落在错误分支，先把提交固定到正确分支（`git branch <name> <sha>`）再恢复，不直接 reset 丢弃。
- **撞车后以磁盘为准合流**。发现同一文件被另一会话重写时，选磁盘上完整且自洽的实现为基线，把自己的剩余价值（接线、测试、文档）改成其上的增量提交，不整文件覆盖回去；合流后尽快提交推送，缩短再次冲突的窗口。
- Git 操作限定本仓库：不在仓库外初始化 Git，不跨仓库统一提交。
- 本地工作产物（构建缓存、媒体素材、评审截图、一次性工具的本地工作区）放 gitignored 目录或仓库外，不进 Git，用完即删。

## 收尾（与 AGENTS.md 分支收尾一致）

任务合并或确认不再继续后：

1. 确认任务提交已进入 `main`，所需检查通过。
2. 回到主目录，同步并切回 `main`。
3. `git worktree remove` 本次任务创建的副本，删除已合并的本地与远端任务分支，`git fetch --prune origin`。
4. 删除前逐项核实：没有主线之外的独有提交、没有未提交或未跟踪文件、没有会话或进程仍在使用。需要保留的先整合或做可恢复备份。
5. 汇报当前分支、清理结果与保留原因。

## 与 Agent 内置 worktree 工具的关系

飞书 Agent 通过 `internal/worktree` 的 Manager 为任务创建隔离工作区（创建、状态、`CommitAndRemove`、`Discard`）。人工与 CLI 会话遵循本页相同纪律；两类副本在 `git worktree list` 中同等对待，收尾时一并核实清理。
