# 个人指挥台原型

> 交互原型：单文件 HTML，内置演示数据，不连接服务、不调用模型、不保存任何内容。只用于讨论产品形态，不代表已实现功能。设计取舍见 [个人指挥台](../../decisions/personal-command-center.md)。

直接用浏览器打开即可，无需构建或网络。

| 文件 | 内容 | 结论 |
|---|---|---|
| [desktop-v1-inbox.html](desktop-v1-inbox.html) | 第一版：收件箱为首页，空间 + 任务 + 执行者 | 收件箱首页保留；仍以任务为中心 |
| [desktop-v3-goals.html](desktop-v3-goals.html) | 第三版：目标（≈ issue）→ 结果（≈ PR / 交付物），会话降为「过程」 | 确定核心模型 |
| [desktop-v4-devices.html](desktop-v4-devices.html) | 第四版：在 v3 上加入设备层，开工时选机器和工具，交接与接手 | 当前桌面端参考 |
| [mobile.html](mobile.html) | 手机端：收件箱 / 目标 / 设备 / 随手聊，随手记，派活与接手 | 当前手机端参考 |

第二版把会话挂在空间下面，以会话为中心，已被 v3 否定，未保留。

## 可以试的交互

**desktop-v4-devices.html**

- 左侧「设备」：每台机器在做什么、装了哪些工具、有什么系统能力；mini 标为中枢。
- 目标 #12：「开工」按完成标准里的设备要求推荐机器，工具列表随机器变化，并生成开工包。
- 目标页「交接到…」：WIP 提交 + 交接说明，换一台机器继续。
- 打开约 8 秒后，模拟 mac 离线，收件箱出现交接包，可在 lx-dev 上接手。
- 收件箱里的服务器压测进度会持续增长，可转给开发机修复。

**desktop-v3-goals.html**

- 收件箱里的「未归属的结果」：git 发现了不属于任何目标的分支，可以挂到目标上或新建目标。
- 目标页：完成标准随结果自动勾选，过程（各工具里的会话）默认折叠。
- 打开约 7 秒后，模拟其他工具推送了新提交，作为新结果进入收件箱。

**mobile.html**

- 打开约 4 秒后弹出系统通知，可直接接手。
- PR 的「看改动」在底部面板里合并或打回。
- 右下角 ＋ 随手记：输入一句话，识别为新目标、补充或问题。
- 目标页「派活」：选机器和工具。

## 原型里还没有反映的决定

原型画完后又确定了两点，以 [设计文档](../../decisions/personal-command-center.md) 为准：

- 执行方式改为**驱动真实的桌面应用**（Codex / Claude 桌面版），不以 `codex exec`、`claude -p` 这类无头模式为主。手机原型里「派活只能用无头模式」的提示已经过时。
- 「问豆包」这类场景要**自动化真实的 App 或网页**，让对话留在用户自己的账号里，不走模型 API。
